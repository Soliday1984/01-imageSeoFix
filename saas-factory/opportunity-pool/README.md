# SaaS Opportunity Pool

这不是“灵感清单”，而是产品矩阵的候选需求单一事实源。目标是在现有资源下，以低成本实验持续寻找能达到 `$1,000 MRR` 的产品。

## 当前资源边界

- 可用：完整 SaaS 母版、Cloudflare、Stripe、美国公司、GitHub、GSC、SEO/内容能力、浏览器自动化。
- 优先：Web 工具、CSV/文件工作流、监控告警、垂直报告、轻量 AI 增值。
- 回避：GPU 重推理、原生移动端、医疗/法律结论、依赖大规模爬虫、需要 24/7 实时音视频、平台审核周期长的产品。
- 并行限制：最多两个产品处于 `building` 或 `live-validation`；其余只做研究和访谈。

## 使用方法

1. 将新机会加入 `opportunities.json`，证据必须包含可访问 URL 和观察日期。
2. 运行 `pnpm pool:check` 检查字段和评分。
3. 运行 `pnpm pool:rank` 生成 `RANKED.md`。
4. 只从前五名中选择下一个验证对象；高分不替代人工 SERP、竞品和用户访谈。
5. 达到预构建门槛后，才用 `create-PRODUCT.ps1` 生成产品。
6. 每次验证复制 `EXPERIMENT_TEMPLATE.md`，把事实结果写回机会状态和评分。

## 状态流转

`discovered -> research -> validate-next -> building -> live-validation -> scale`

任何阶段都可以进入 `hold` 或 `killed`。`avoid` 用于保留反例，防止以后重复研究拥挤赛道。

## 四道门

### 1. 需求门

- 能写清楚谁在什么时刻遇到什么损失。
- 输入、处理、输出明确，结果可以被用户验证。
- 至少找到 3 条独立用户抱怨，或拿到 2 份真实文件/样本。

### 2. 触达门

- 至少有一个无需大量广告预算的渠道：Google 长尾词、垂直社区、应用生态、定向外联。
- 能列出首批 30 个潜在用户或 10 个可参与讨论的社区/关键词入口。

### 3. 付款门

- 买家和使用者明确。
- 在写完整产品前测试价格页、付款意向或人工服务。
- `$1,000 MRR` 路径成立：35 人 x `$29`、21 人 x `$49`，或可解释的一次性购买补充策略。

### 4. 交付门

- MVP 目标 3-10 个开发日。
- 结果能自动交付，毛利目标高于 80%。
- 有限额、验证码、速率限制和成本熔断，不允许“免费无限 AI”。

## 验证节奏

- 第 1-2 天：SERP、竞品、评论和社区问题，补齐证据。
- 第 3 天：落地页、样例结果和价格测试。
- 第 4-7 天：只为真实样本做最短交付路径。
- 上线 14 天：目标 100 个定向访问或 20 次直接对话、10 次成功交付、3 次升级意向、至少 1 笔付款。
- 未达门槛：记录原因并 `hold/killed`，不因沉没成本继续开发。
- SEO 产品另设 30/60/90 天观察，不用 14 天无自然流量直接判死刑，但必须同步做直接触达。

## 评分说明

每项 1-5 分。正向权重：痛点 18%、可触达性 16%、开发速度 14%、付费意愿 18%、复购 10%、SEO 10%、毛利 8%、防御性 6%；执行风险每级扣 2.4 分。

评分负责排序，阶段门负责决策。榜单收入只是需求证据之一，不等于可复制收入。
